## Context

当前网站使用 React 19 + TypeScript + Vite + Tailwind CSS + shadcn/ui。主题系统位于 `src/lib/theme.tsx`，通过 `dark:` 类控制深色/浅色模式。现有背景为纯色（白色/深灰），页面内容使用 GSAP + ScrollTrigger 实现滚动动画。

约束条件：
- 不能影响现有内容的布局、动画和交互
- 需保持良好的移动端性能
- 支持"减少动画"的无障碍适配

## Goals / Non-Goals

**Goals:**
- 实现沉浸式的"晴空微雨"浅色主题和"星空点点"深色主题
- 与现有主题系统无缝集成
- 保持流畅的动画性能（目标 60fps）
- 支持平滑的主题切换过渡

**Non-Goals:**
- 不修改现有页面内容和组件
- 不改变现有 GSAP 动画系统
- 不添加用户可配置的背景自定义选项

## Decisions

### 1. 背景层架构
**决策**: 使用固定定位的背景层组件，独立于内容层

**原因**:
- 不影响现有布局流
- 便于 z-index 控制
- 独立的动画生命周期

**替代方案**:
- 修改 `body` 背景 → 难以实现复杂动画层叠
- 各 section 独立背景 → 重复代码、不一致

---

### 2. 渲染技术选择
**决策**: 
- 天空/云朵/月亮光晕 → CSS + 动画
- 雨滴/星星/流星 → Canvas 渲染

**原因**:
- CSS 适合渐变和简单动画
- Canvas 在大量粒子时性能更好（50+ 星星、雨滴）
- 组合方案平衡开发效率和性能

**替代方案**:
- 纯 CSS → 大量 DOM 元素，移动端性能差
- 纯 Canvas → 云朵形状实现复杂
- WebGL → 过度工程，兼容性问题

---

### 3. 性能优化策略
**决策**:
- 使用 `prefers-reduced-motion` 检测禁用动画
- 移动端粒子数量减半
- 使用 `requestAnimationFrame` 节流
- 背景动画在不可见时暂停（IntersectionObserver）

**原因**: 平衡视觉效果和设备性能

---

### 4. 主题切换过渡
**决策**: 双层淡入淡出 + CSS 过渡

**原因**: 简单有效，用户体验流畅

**替代方案**: 逐帧 morph → 实现复杂，收益不高

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 低端设备性能下降 | 动画卡顿 | 自动检测性能降级，粒子数量自适应 |
| 电池消耗增加 | 移动端续航 | 页面不可见时暂停动画 |
| 与现有 GSAP 冲突 | 动画异常 | 独立层设计，z-index 严格控制 |
| 内存占用增加 | 浏览器变慢 | Canvas 及时释放资源，粒子池复用 |
